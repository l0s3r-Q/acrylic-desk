# 03 · 窗体与亚克力技术方案

> 本文档是本项目技术难度最高的部分，涵盖亚克力材质、边缘吸附、碰边唤出、
> 鼠标穿透的完整实现方案与已知陷阱。

## 1. 亚克力材质实现

### 1.1 方案选择

| 方案 | 实现 | 优点 | 缺点 | 采纳 |
|---|---|---|---|---|
| **A. Tauri 内置 Effect** | `WindowEffectsConfig` | 官方支持、跨版本稳定、代码量最少 | 可调参数少 | ✅ **主方案** |
| B. DWM 系统背景 | `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` | Windows 11 原生 Mica/Acrylic | 需 Win11 22H2+，Win10 不支持 | 备用降级 |
| C. 未文档化 API | `SetWindowCompositionAttribute` | 可精确控制 tint/opacity | 微软未公开，可能随时失效 | 兜底方案 |

**采纳方案 A**，依据来自 `tauri-utils 2.10.1` 源码实测（见文档 00 §4.1）：
`Acrylic` 是官方 `WindowEffect` 枚举成员。

### 1.2 配置写法


### 1.3 ⚠️ 陷阱一：Acrylic 的拖拽性能问题

**官方源码注释原文**：

> `Acrylic`: This effect has bad performance when resizing/dragging the window
> on Windows 10 v1903+ and Windows 11 build 22000.

**现象**：窗口移动/缩放时明显掉帧、卡顿。

**应对**：本项目采用**动画期材质降级**策略。

```rust
#[tauri::command]
async fn set_panel_effect(window: tauri::Window, mode: String) -> Result<(), String> {
    let effect = match mode.as_str() {
        "quality" => WindowEffect::Acrylic,   // 静止时：最佳视觉
        "performance" => WindowEffect::Blur,  // 动画时：流畅优先
        _ => return Err("unknown mode".into()),
    };
    window.set_effects(WindowEffectsConfig {
        effects: Some(vec![effect]),
        state: None,
        radius: Some(12.0),
        color: None,
    }).map_err(|e| e.to_string())
}
```

前端在滑入/滑出动画的生命周期中调用：

```ts
async function slideOut() {
  await invoke('set_panel_effect', { mode: 'performance' });
  await animate(...);
  await invoke('set_panel_effect', { mode: 'quality' });
}
```

### 1.4 ⚠️ 陷阱二：WebView2 透明区域显示黑底

**现象**：设置了 `transparent: true`，但 WebView 未绘制区域显示为黑色而非透明。

**根因**：WebView2 默认背景不透明。Tauri 已设 `transparent`，但 CSS 层若设置了
不透明背景色，就会遮挡住亚克力。

**应对**（三层都要做对）：

```css
/* 1. html/body 必须完全透明 */
html, body {
  background: transparent !important;
  margin: 0;
  padding: 0;
  overflow: hidden;
}

/* 2. 根容器透明 */
#app {
  background: transparent;
}

/* 3. 只有"面板实体"才有半透明背景，且必须是 rgba */
.panel-surface {
  background: rgba(32, 32, 36, 0.35);  /* 注意：必须用 rgba，不能用 hex */
  backdrop-filter: blur(20px);          /* 前端再叠一层模糊，增强质感 */
  border-radius: 12px;
}
```

> **要点**：`backdrop-filter` 在 WebView2 中需要 Chromium 76+，
> 本机 WebView2 为 154，完全支持。它与系统 Acrylic **可以叠加**，
> 视觉效果比单用任一层都更好。

### 1.5 ⚠️ 陷阱三：Win10 回退

Windows 10 2004–21H2 不支持 Mica，Acrylic 在部分版本表现不佳。

**应对**：启动时检测系统版本，Win10 上优先 `Blur`，并提供"强制纯色"选项兜底。

```rust
fn pick_default_effect() -> WindowEffect {
    // Windows 11 build 22000+
    if is_windows_11() { WindowEffect::Acrylic }
    else { WindowEffect::Blur }
}
```

## 2. 边缘吸附与定位

### 2.1 坐标系约定

Windows 有**物理像素**与**逻辑像素**两套坐标，混用是错位的主要根源。

| 概念 | 单位 | 获取方式 |
|---|---|---|
| 物理像素 | px | `GetCursorPos` / `GetMonitorInfo` |
| 逻辑像素 | DIP | 物理像素 / DPI缩放 |
| DPI 缩放 | 1.0/1.25/1.5/2.0… | `GetDpiForWindow` |

**项目约定**：
- **Rust 侧所有计算使用物理像素**
- **传给前端的尺寸使用逻辑像素**（Tauri 的 `LogicalSize`）
- 转换点集中在 `edge/geometry.rs`，其他地方禁止自行换算

### 2.2 四边位置计算

设：
- 显示器工作区：`(mx, my, mw, mh)`
- 面板尺寸：`(pw, ph)` —— 注意：**左右挂载时 pw=厚度，ph=长度；上下挂载时相反**
- 边缘偏移：`offset`

```rust
pub fn compute_position(edge: Edge, mon: WorkArea, size: Size, offset: i32, visible: bool) -> (i32, i32) {
    match edge {
        Edge::Left => (
            if visible { mon.x + offset } else { mon.x - size.w },
            mon.y + (mon.h - size.h) / 2,   // 垂直居中
        ),
        Edge::Right => (
            if visible { mon.x + mon.w - size.w - offset } else { mon.x + mon.w },
            mon.y + (mon.h - size.h) / 2,
        ),
        Edge::Top => (
            mon.x + (mon.w - size.w) / 2,   // 水平居中
            if visible { mon.y + offset } else { mon.y - size.h },
        ),
        Edge::Bottom => (
            mon.x + (mon.w - size.w) / 2,
            if visible { mon.y + mon.h - size.h - offset } else { mon.y + mon.h },
        ),
    }
}
```

**关键点**：
- 面板尺寸随挂载边变化。切到左/右时，长度对应屏幕**高度**；切到上/下时，长度对应屏幕**宽度**。
- 隐藏位置必须**完全移出屏幕**（`x = mon.x - size.w`，而非 `x = mon.x - 1`），
  否则会露出边缘。用 `offset = 0` 时留 1px 是常见做法，但会导致鼠标在边缘误触。

### 2.3 面板尺寸切换矩阵

| 挂载边 | 窗口宽 (w) | 窗口高 (h) | "长度"设置项 | "厚度"设置项 |
|---|---|---|---|---|
| Left | 厚度 | 长度 | 影响 h | 影响 w |
| Right | 厚度 | 长度 | 影响 h | 影响 w |
| Top | 长度 | 厚度 | 影响 w | 影响 h |
| Bottom | 长度 | 厚度 | 影响 w | 影响 h |

切换挂载边时必须**同步交换 width/height**，这是容易漏掉的一步。

## 3. 碰边唤出机制

### 3.1 为什么用轮询而非全局钩子

**这是本项目的安全红线决策**，必须说明清楚。

| 方案 | 杀软风险 | CPU | 稳定性 | 采纳 |
|---|---|---|---|---|
| `WH_MOUSE_LL` 低级鼠标钩子 | ❌ **极高** —— 与键盘记录器/远控行为特征一致，国产杀软必报 | 低 | 钩子超时会被系统摘除 | ❌ |
| `GetCursorPos()` 轮询 @60Hz | ✅ **无** —— 只读查询，行为无害 | 实测 <0.1% | 稳定 | ✅ |

**决策**：采用轮询。理由：

1. 用户 P0 约束是"不被杀毒软件拦截"，全局钩子会直接违背
2. 60Hz 轮询的 CPU 开销实测低于 0.1%，性能上完全够用
3. 响应延迟 <16ms，人类感知不到
4. 实现简单、无权限要求、不会崩溃

### 3.2 监测线程实现

```rust
pub fn spawn_edge_monitor(state: Arc<Mutex<EdgeState>>, app: AppHandle) {
    std::thread::spawn(move || {
        let mut last_inside = false;
        loop {
            std::thread::sleep(Duration::from_millis(16)); // ~60Hz

            let (mx, my) = get_cursor_pos();
            let cfg = state.lock().unwrap().config.clone();

            // 1. 判断是否在触发区
            let in_trigger = is_in_trigger_zone(mx, my, &cfg);
            // 2. 判断是否在面板矩形内
            let in_panel = is_in_panel_rect(mx, my, &cfg);

            if in_trigger && !state.lock().unwrap().is_visible {
                summon(&app, &state);
            } else if !in_panel && state.lock().unwrap().is_visible {
                schedule_hide(&app, &state);   // 启动延时计时
            } else if in_panel {
                cancel_hide(&state);           // 取消收起
            }

            // 3. 全屏应用检测（可选）
            if cfg.disable_on_fullscreen && is_fullscreen_app_active() {
                force_hide(&app, &state);
            }
        }
    });
}
```

### 3.3 显隐状态机

```
        ┌──────────────────────────────────────────┐
        │                                          │
        ▼                                          │
   ┌─────────┐  鼠标进触发区   ┌──────────┐        │
   │ Hidden  │───────────────▶│ Showing  │        │
   │ (穿透)   │                │ (动画中)  │        │
   └─────────┘                └────┬─────┘        │
        ▲                          │ 动画结束      │
        │                          ▼              │
        │                     ┌──────────┐        │
        │   动画结束           │ Visible  │        │
        │  ┌──────────┐◀──────│ (交互中)  │        │
        └──│  Hiding  │  鼠标离开+延时到期 └───────┘
           │ (动画中)  │                        ▲
           └──────────┘                  鼠标返回面板
                                            (取消收起)
```

**状态定义**：

| 状态 | 窗口位置 | 鼠标穿透 | 材质 |
|---|---|---|---|
| Hidden | 屏幕外 | ✅ 穿透 | Acrylic |
| Showing | 动画中 | ❌ 接管 | **Blur** |
| Visible | 屏幕内 | ❌ 接管 | Acrylic |
| Hiding | 动画中 | ❌ 接管 | **Blur** |

**关键约束**：
- 状态转换必须是**原子**的，用 `Mutex<EdgeState>` 保护
- `Hiding → Visible` 的取消路径必须支持（用户快速移回鼠标）
- 正在拖拽图标时**禁止收起**（`is_dragging` 标志）

### 3.4 触发区判定

```rust
fn is_in_trigger_zone(mx: i32, my: i32, cfg: &EdgeConfig) -> bool {
    let mon = get_monitor_work_area(cfg.monitor_index);
    let t = cfg.trigger_width; // 默认 3px

    match cfg.edge {
        Edge::Left   => mx >= mon.x && mx <= mon.x + t
                        && my >= mon.y && my <= mon.y + mon.h,
        Edge::Right  => mx >= mon.x + mon.w - t && mx <= mon.x + mon.w
                        && my >= mon.y && my <= mon.y + mon.h,
        Edge::Top    => my >= mon.y && my <= mon.y + t
                        && mx >= mon.x && mx <= mon.x + mon.w,
        Edge::Bottom => my >= mon.y + mon.h - t && my <= mon.y + mon.h
                        && mx >= mon.x && mx <= mon.x + mon.w,
    }
}
```

> **注意**：使用**工作区** (`GetMonitorInfo.rcWork`) 而非全屏区域 (`rcMonitor`)，
> 这样如果任务栏在同侧，触发区会自动让开任务栏，不会与任务栏冲突。

### 3.5 ⚠️ 陷阱四：屏边缘的"死角"

Windows 有**边缘吸附保护**（如鼠标撞左上角触发 Win11 手势），
且部分显示器边缘存在 1px 不可达区域。

**应对**：
- 默认 `trigger_width = 3px` 而非 1px，提高容错
- 提供 `trigger_width` 可调（1–20px）
- 若用户报告唤不出，引导调大该值

### 3.6 ⚠️ 陷阱五：与任务栏自动隐藏冲突

若系统开启了"任务栏自动隐藏"，且面板挂在同侧，会与任务栏唤出冲突。

**应对**：
- 检测任务栏自动隐藏状态
- 若冲突，提示用户或自动把触发区偏移到任务栏区域之外
- 提供"覆盖任务栏"选项

## 4. 鼠标穿透控制

### 4.1 实现

Tauri 提供 `set_ignore_cursor_events(bool)`：

```rust
#[tauri::command]
async fn set_passthrough(window: tauri::Window, enabled: bool) -> Result<(), String> {
    window.set_ignore_cursor_events(enabled).map_err(|e| e.to_string())
}
```

对应 Win32 层面是切换 `WS_EX_TRANSPARENT | WS_EX_LAYERED` 扩展样式。

### 4.2 穿透策略

| 面板状态 | 穿透 | 理由 |
|---|---|---|
| 完全收起 | ✅ 开启 | 面板在屏幕外，且要保证不影响桌面操作 |
| 任何动画中 | ❌ 关闭 | 避免动画期间鼠标事件丢失 |
| 展开显示 | ❌ 关闭 | 正常交互 |

### 4.3 ⚠️ 陷阱六：穿透状态下的残留鼠标事件

**现象**：开启穿透后，WebView 仍可能收到最后一次鼠标位置的事件，
或 CSS `:hover` 状态卡住。

**应对**：
- 进入穿透前，前端主动清除所有 hover 状态
- 发送 `edge://hidden` 事件让前端重置 UI 状态

```ts
listen('edge://hidden', () => {
  document.querySelectorAll('.hovered').forEach(el => el.classList.remove('hovered'));
  isDragging.value = false;
});
```

### 4.4 ⚠️ 陷阱七：拖拽与穿透互斥

从面板拖出文件到桌面时，若面板此时开启穿透，拖拽会中断。

**应对**：拖拽期间锁定穿透为 `false`，并设置 `is_dragging` 标志阻止收起。

## 5. 窗口动画方案

### 5.1 方案对比

| 方案 | 实现 | 流畅度 | 与亚克力配合 | 采纳 |
|---|---|---|---|---|
| **Rust 侧逐帧 set_position** | 循环调用窗口定位 | 中（受 IPC 影响小） | 好 | ✅ |
| 前端 CSS transform | 窗口固定，内容位移 | 高 | ❌ 窗口不动，露不出屏 | ❌ |
| Windows 原生动画 | `AnimateWindow` | 差（不支持亚克力） | ❌ | ❌ |

**问题**：面板需要**窗口本身**移出屏幕，CSS 只能动内容，所以必须用窗口移动。

**采纳**：Rust 侧用缓动函数逐帧 `set_position`，每帧间隔 8ms（~120fps 目标）：

```rust
fn animate_window(window: &Window, from: (i32,i32), to: (i32,i32), duration_ms: u64) {
    let steps = (duration_ms / 8).max(1) as usize;
    for i in 0..=steps {
        let t = i as f64 / steps as f64;
        let eased = ease_out_cubic(t);          // 缓动
        let x = lerp(from.0, to.0, eased);
        let y = lerp(from.1, to.1, eased);
        let _ = window.set_position(PhysicalPosition::new(x, y));
        std::thread::sleep(Duration::from_millis(8));
    }
}
```

**缓动函数**（`ease_out_cubic` 最适合面板滑出，先快后慢）：

```rust
fn ease_out_cubic(t: f64) -> f64 {
    1.0 - (1.0 - t).powi(3)
}
```

### 5.2 ⚠️ 陷阱八：动画期间的材质抖动

逐帧移动窗口时，Acrylic 会持续重算模糊，导致卡顿。

**应对**：动画开始前切 `Blur`，结束后切回 `Acrylic`（见 §1.3）。

## 6. 多显示器与 DPI

### 6.1 显示器枚举

```rust
fn enumerate_monitors() -> Vec<MonitorInfo> {
    // 使用 EnumDisplayMonitors + GetMonitorInfoW
    // 返回每个显示器的: 序号、名称、物理工作区、是否主屏、DPI
}
```

### 6.2 ⚠️ 陷阱九：负坐标显示器

多显示器时，副屏可能位于主屏**左侧或上方**，坐标**为负**。

**应对**：所有坐标计算必须使用 `i32`（有符号），禁止 `u32`。

### 6.3 ⚠️ 陷阱十：DPI 缩放变化

用户在运行时修改缩放比例（如 100% → 150%），窗口会错位。

**应对**：
- 监听 `WM_DPICHANGED` 消息
- 收到后重新计算面板尺寸与位置
- 重新设置窗口尺寸（物理像素）

### 6.4 ⚠️ 陷阱十一：显示器热插拔

拔掉显示器后，原本挂在上面的面板会跑到屏幕外。

**应对**：
- 监听 `WM_DISPLAYCHANGE`
- 若面板所属显示器消失，自动迁移到主显示器
- 恢复后不自动迁回（避免显示器闪烁时面板乱跳）

### 8.3 ⚠️ 陷阱十二：DPI 坐标系混用（已修复）

**现象**：面板实际尺寸为 `183×411` 而非配置的 `320×720`。

**根因**：
- Win32 `GetMonitorInfo` 返回**物理像素**
- Tauri 窗口 API 使用**逻辑像素**（DIP）
- 代码用物理像素算位置，却用 `PhysicalSize` 传尺寸，导致二次缩放

**修复**（见 `edge/geometry.rs::scale_rect` 与 `edge/state.rs::work_rect`）：

1. 把 Win32 返回的物理工作区，按窗口 `scale_factor()` 换算为逻辑工作区
2. 鼠标位置同样由物理换算为逻辑
3. 窗口尺寸/位置统一使用 `LogicalSize` / `LogicalPosition`

> **教训**：坐标换算必须**集中在一处**，且明确标注每个数据源的坐标系。
> 本项目的换算点：`geometry.rs::scale_rect` 与 `state.rs::work_rect`。

### 8.4 ⚠️ 陷阱十三：启动瞬间被收起

**现象**：应用启动后，面板立刻被判定为"鼠标不在面板内"而收起，
用户看不到面板出现在哪里，会以为程序没运行。

**修复**：引入 **4 秒启动宽限期**（`STARTUP_GRACE`）：

```rust
if let Some(t0) = *self.started_at.lock().unwrap() {
    if t0.elapsed() < STARTUP_GRACE {
        continue;   // 宽限期内不做收起判定
    }
}
```

### 8.5 ⚠️ 陷阱十四：屏幕截图无法捕获分层窗口

**现象**：用 `CopyFromScreen` 截图时，捕获到的是面板**下方**的窗口内容，
看起来像"面板没显示"。

**根因**：面板启用了 `WS_EX_LAYERED`（透明窗口必需），
这类窗口不参与常规屏幕合成，屏幕截图 API 会"穿透"过去。

**正确验证方式**：使用 `PrintWindow(hwnd, hdc, 2)`
（`flag 2` = `PW_RENDERFULLCONTENT`，可捕获 DirectComposition 内容）。

```powershell
# 正确的截图验证方式
$bmp = New-Object System.Drawing.Bitmap($w, $h)
$g = [System.Drawing.Graphics]::FromImage($bmp)
$hdc = $g.GetHdc()
[PW]::PrintWindow($hwnd, $hdc, 2)   # 关键：flag = 2
$g.ReleaseHdc($hdc)
$bmp.Save($out, [System.Drawing.Imaging.ImageFormat]::Png)
```

> **注意**：这是**验证手段**的坑，不是产品 bug。
> 面板本身显示正常，只是普通截图看不到。

### 8.6 ⚠️ 陷阱十五：隐藏窗口首次显示为空白

**现象**：设置窗口在 `tauri.conf.json` 中配置为 `visible: false`，
通过托盘或齿轮按钮打开后，窗口显示为**纯黑/空白**，
拖动窗口或改变其大小后才正常渲染。

**根因**：Tauri（wry）对**创建时不可见**的窗口会**延迟 WebView 的首次合成**。
若仅调用 `Window::show()`，窗口框架显示了，但 WebView 表面尚未绘制。

**验证方法**：枚举子窗口可确认 WebView 已创建且尺寸正确：

```
WRY_WEBVIEW | 880x640
Chrome_WidgetWin_0 | 880x640
Chrome_WidgetWin_1 | 880x640
```

（WebView 存在 → 不是创建失败，而是**未合成**）

**修复**：`show()` 之后主动触发一次重绘：

```rust
window.show()?;
window.set_focus()?;

// 强制重绘：位置挪动 1px 再移回
if let Ok(pos) = window.outer_position() {
    let _ = window.set_position(PhysicalPosition::new(pos.x + 1, pos.y));
    let _ = window.set_position(PhysicalPosition::new(pos.x, pos.y));
}
```

**注意**：托盘菜单与 `open_settings` 命令**两条路径都要处理**，
否则会出现"从托盘打开正常、从面板打开空白"这类不一致行为。

### 8.7 ⚠️ 陷阱十六：外部 ShowWindow 绕过 Tauri 状态

**现象**：用 Win32 `ShowWindow()` 或 `SetForegroundWindow()` 从外部
强制显示设置窗口时，窗口看似可见，但内容仍为空白，
且窗口位置可能被移动到 `-18286,-18286`（最小化坐标）。

**根因**：Tauri 维护自己的窗口状态机（visible/focused/minimized）。
外部 Win32 调用**绕过了这个状态机**，导致：
- Tauri 认为窗口仍隐藏 → 不触发 WebView 合成
- 状态不一致 → 位置/焦点行为异常

**正确做法**：始终通过 Tauri API（`show()`/`set_focus()`）
或调用应用自己的命令（`open_settings`）来显示窗口。

> **给自动化测试的提示**：验证窗口渲染时，
> 不要用 `ShowWindow` 强行显示，而应先模拟用户操作
> （如点击面板齿轮按钮）触发应用自身的显示逻辑。
