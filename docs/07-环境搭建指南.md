## 2. ⚠️ 本机特有陷阱：Smart App Control 拦截 cargo 编译

### 2.1 现象

执行 `cargo install tauri-cli` 时报错：

```
error: failed to run custom build command for `slab v0.4.9`
Caused by:
  could not execute process `...\build-script-build.exe` (never executed)
Caused by:
  应用程序控制策略已阻止此文件。 (os error 4551)
```

### 2.2 根因

经查证 Windows 事件日志
（`Microsoft-Windows-CodeIntegrity/Operational`，事件 ID 3077）：

```
Code Integrity determined that a process
  (\Device\HarddiskVolume2\Users\Q\.rustup\toolchains\...\cargo.exe)
  attempted to load
  \Device\HarddiskVolume4\全局\AcrylicDesk\...\build-script-build.exe
  that did not meet the Enterprise signing level requirements
  or violated code integrity policy
  (Policy ID:{0283ac0f-fff1-49ae-ada1-8a933130cad6})
```

**本机启用了 Smart App Control**（`VerifiedAndReputablePolicyState = 1`），
叠加活动 WDAC 策略，导致：

> cargo 在构建依赖时，若某依赖含 **build script**，
> cargo 需要**执行自己刚编译出来的、未签名的 `build-script-build.exe`**。
> Smart App Control 阻止了这个执行。

### 2.3 影响范围（实测边界）

| 操作 | 结果 | 说明 |
|---|---|---|
| `cargo build`（debug，含 build script） | ✅ 通过 | debug 产物放行 |
| `cargo build --release`（**无** build script） | ✅ 通过 | 编译本身没问题 |
| `cargo build --release`（**含** build script） | ❌ 拦截 | 无法执行未签名 build script |
| `cargo install <crate>`（依赖树含 build script） | ❌ 拦截 | 同上 |
| 编译产物的**执行** | ✅ 通过 | 仅构建期的 build script 受限 |

**关键结论**：被拦的不是"release 构建"，而是**构建过程中执行未签名 build-script** 这一步。

### 2.4 解决方案（已验证）

**不要用 `cargo install` 安装 Tauri CLI**，改用 npm 上的官方预编译包：

```powershell
npm install --save-dev @tauri-apps/cli@^2
```

`@tauri-apps/cli-win32-x64-msvc` 是 **Tauri 官方预编译并签名的二进制**，
无需本地编译，直接绕开该限制。

**验证**：

```powershell
.\node_modules\.bin\tauri.cmd --version
# 输出: tauri-cli 2.12.1
```

### 2.5 ⚠️ 对项目构建的潜在影响

**需要持续关注**：若项目依赖树中出现**含 build script 的 crate**，
`cargo build --release` 可能失败。

**应对预案**：

| 情况 | 应对 |
|---|---|
| 依赖无 build script | 正常构建 |
| 依赖含 build script 且被拦 | ① 优先选用无 build script 的替代 crate<br>② 在 `%TEMP%` 外的目录构建（已配置）<br>③ 极端情况下，请用户评估关闭 Smart App Control |
| 构建成功但产物无法运行 | 属正常现象，产物在 `target/` 外执行不受限 |

**项目当前对策**：将 `CARGO_TARGET_DIR` 与 `TMP`/`TEMP` 全部重定向到项目目录，
减少触发概率（见 §3）。

### 2.6 关于关闭 Smart App Control

> ⚠️ **关闭 Smart App Control 不可逆** —— 关闭后只能通过重装系统重新开启。

**本项目已关闭 SAC**，原因有两个：

1. **构建阻塞**：SAC 拦截 cargo 执行自己编译出的 build-script，
   `serde_json`、`url` 等 Tauri 核心依赖全部无法编译。
2. **产物无法运行**：本项目分发的绿色版 exe **未做代码签名**，
   SAC 开启时会直接拦截它，用户双击无反应。

第 2 点是决定性的——**即使解决了编译问题，SAC 开着软件也跑不起来**。

关闭后状态确认：

```powershell
(Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy").VerifiedAndReputablePolicyState
# 0 = 已关闭
```

关闭方式（管理员权限）：

```
设置 → 隐私和安全性 → Windows 安全中心
     → 应用和浏览器控制 → 智能应用控制 → 关闭
```

或注册表：

```powershell
Set-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy" `
  -Name "VerifiedAndReputablePolicyState" -Value 0 -Type DWord
Restart-Computer
```

> **给其他开发者的提示**：若因安全策略无法关闭 SAC，
> 可考虑以下替代路径（本项目未采用，仅供参考）：
> - 购买代码签名证书（EV 证书可让 SAC 放行）
> - 在关闭 SAC 的虚拟机/独立环境中开发
> - 改用不依赖 build script 的技术栈（但 Tauri 核心依赖难以避开）

## 3. 环境变量配置（项目约定）

为规避 §2 问题并保证构建稳定，项目统一使用以下路径：

```powershell
# 加入 shell profile 或在构建脚本中设置（路径按你的实际克隆位置调整）
$root = "D:\Projects\AcrylicDesk"          # ← 改成你的项目根目录
$env:CARGO_TARGET_DIR = "$root\artifacts\_cargo-target"
$env:TMP  = "$root\artifacts\_tmp"
$env:TEMP = "$root\artifacts\_tmp"
```

**理由**：
1. 避开 `%TEMP%` —— Smart App Control 对临时目录管控最严
2. 集中构建缓存，便于清理
3. 不占用系统盘空间

**持久化配置**（可选，写入用户环境变量）：

```powershell
$root = "D:\Projects\AcrylicDesk"          # ← 改成你的项目根目录
[Environment]::SetEnvironmentVariable("CARGO_TARGET_DIR", "$root\artifacts\_cargo-target", "User")
```

## 6. 故障排查

| 症状 | 原因 | 解决 |
|---|---|---|
| `os error 4551` 应用程序控制策略阻止 | Smart App Control 拦截 build script | 见 §2.4，改用预编译包 |
| 面板显示黑底而非透明 | CSS 背景不透明 | 见文档 03 §1.4，三层透明都要设 |
| 亚克力不可见 | 效果未应用或系统不支持 | 检查 `effects` 配置；Win10 降级为 `Blur` |
| 碰边无反应 | 触发区太窄 | 调大 `trigger_width` 至 5–10px |
| 面板错位 | DPI 缩放变化 | 见文档 03 §6.3 |
| 编译很慢 | 首次编译 + 无缓存 | 正常，二次编译会快很多 |
| `cargo install` 失败 | 同 4551 | 用 npm 版 CLI |
