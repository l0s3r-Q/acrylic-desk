## 2. 进程与线程模型

### 2.1 进程结构

Tauri 应用包含两个主要执行体：

| 执行体 | 语言 | 职责 |
|---|---|---|
| **主进程 (Rust)** | Rust | 窗口管理、系统 API 调用、文件操作、边缘监测、配置持久化 |
| **WebView 渲染进程** | Web (Vue 3) | UI 渲染、用户交互、动画表现 |

两者通过 Tauri IPC 通信，**所有系统级操作必须经 Rust 侧完成**（Web 侧无系统权限）。

### 2.2 Rust 侧线程规划

| 线程 | 用途 | 频率 |
|---|---|---|
| 主线程 | Tauri 事件循环、窗口操作 | 事件驱动 |
| **边缘监测线程** | 轮询鼠标位置，判断是否触发唤出 | 60 Hz（16ms） |
| 图标提取线程池 | 异步提取 exe/lnk 图标，避免阻塞 UI | 按需 |
| 配置写入线程 | 防抖写入配置文件 | 防抖 500ms |

> **设计决策**：边缘监测采用 **轮询** 而非 `WH_MOUSE_LL` 低级钩子。
>
> 理由：
> - 低级鼠标钩子需要注入全局钩子链，**极易被国产杀软判定为键盘记录/远控行为**（直接违背 P0 约束）
> - 轮询 `GetCursorPos()` 是无害的只读调用，零杀软风险
> - 16ms 轮询的 CPU 开销实测 < 0.1%，完全可接受
> - 实现更简单、更稳定，不会因钩子超时被系统摘除
>
> 这是**安全性与性能权衡后的明确取舍**，而非妥协。

## 4. 关键技术决策

### 4.1 为什么边缘监测用轮询而非全局钩子

见 §2.2 说明。**这是本项目的安全红线**：全局钩子是杀软重点监控行为，
与"不被杀毒拦截"的 P0 约束直接冲突。

### 4.2 亚克力材质降级策略

Tauri 官方源码注释指出 `Acrylic` 在拖拽/缩放时有性能问题（详见文档 00 §4.2）。
本项目采用**动态材质切换**：

```rust
// 伪代码
fn on_slide_animation_start(window: &Window) {
    window.set_effects(WindowEffectsConfig {
        effects: vec![WindowEffect::Blur],  // 动画期用轻量材质
        ..default
    });
}

fn on_slide_animation_end(window: &Window) {
    window.set_effects(WindowEffectsConfig {
        effects: vec![WindowEffect::Acrylic],  // 恢复
        ..default
    });
}
```

前端通过 Tauri 命令在动画生命周期中调用。

### 4.3 面板窗口的窗口样式

面板需要以下窗口特性组合：

| 特性 | 实现方式 | 目的 |
|---|---|---|
| 无边框 | `decorations: false` | 去掉标题栏 |
| 透明 | `transparent: true` | 允许亚克力透出 |
| 不显示在任务栏 | `skipTaskbar: true` | 面板不该占任务栏位置 |
| 不进 Alt+Tab | `WS_EX_TOOLWINDOW` | 避免出现在切换列表 |
| 置顶 | `alwaysOnTop: true`（可配） | 保证可见 |
| 无阴影 | `shadow: false` | 避免透明区域出现方框阴影 |
| 无焦点抢占 | `WS_EX_NOACTIVATE`（可选） | 唤出时不夺走当前窗口焦点 |

> ⚠️ `WS_EX_NOACTIVATE` 与 `WS_EX_TOOLWINDOW` 需通过 Win32 API 直接设置，
> Tauri 配置项覆盖不全。

### 4.4 配置存储位置

采用**便携式存储**，与绿色版分发策略一致：

```
<exe所在目录>/data/
├── config.json      # 主配置
├── icons/           # 提取的图标缓存 (PNG)
└── backups/         # 配置备份（保留最近5份）
```

若 exe 所在目录不可写（如放在 `Program Files`），则回退到
`%APPDATA%\AcrylicDesk\`。

**理由**：便携式存储让用户可以把整个文件夹拷走即完成迁移，
且不污染系统目录，符合绿色软件定位。

## 5. 数据流

### 5.1 碰边唤出流程

```
[边缘监测线程] 每16ms GetCursorPos()
      │
      ├─ 鼠标在触发区内?
      │        │ 是
      │        ▼
      │  [EdgeState] Hidden → Showing
      │        │
      │        ├─ 发事件 edge://summon 给前端
      │        ├─ set_ignore_cursor_events(false)
      │        ├─ set_effects(Blur)          ← 动画期降级
      │        └─ 启动窗口位移动画 (Rust侧 set_position 循环 或 前端CSS)
      │                 │
      │                 ▼ 动画结束
      │            [EdgeState] Showing → Visible
      │                 ├─ set_effects(Acrylic)  ← 恢复
      │                 └─ 启动离开检测
      │
      └─ 鼠标离开面板 && 延时到期?
               │ 是
               ▼
         [EdgeState] Visible → Hiding
               ├─ set_effects(Blur)
               ├─ 窗口位移动画
               └─ 动画结束 → Hidden
                    ├─ set_effects(Acrylic)
                    └─ set_ignore_cursor_events(true)  ← 穿透
```

### 5.2 图标添加流程

```
用户拖入文件到面板
      │
      ▼
WebView 捕获 drop 事件 → 取得路径
      │  (注意: WebView 无法直接读本地文件系统)
      ▼
invoke('add_icon', { path })
      │
      ▼
[Rust] 判断类型:
      ├─ .lnk  → IShellLink 解析目标路径 + 参数
      ├─ .exe  → 直接使用
      ├─ 目录   → 标记为文件夹类型
      ├─ 其他文件 → 标记为文件类型（用关联程序打开）
      └─ http(s):// → URL 类型
      │
      ▼
SHGetFileInfo / IExtractIcon 提取图标
      │
      ▼
转为 PNG 存入 data/icons/<hash>.png
      │
      ▼
更新 config.json → 发事件 config://changed
      │
      ▼
前端刷新列表
```
